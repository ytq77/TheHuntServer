# The Hunt · Windows 原生私服测试版

这是独立仓库的 Windows 原生预览包，无需 Docker，无需另装 Qt 或 Python。目标系统为 Windows 10/11 x64。

## 使用管理窗口

1. 完整解压后双击 `Server.exe`，选择「普通联机」或「BBSC 无缝联机」。`Server.cmd` 也会打开同一个窗口。
2. 点击「本机地址」，选择开服电脑的实际局域网或 VPN IPv4，再点击「启动服务」。Tailscale 网卡已连接时，其地址会出现在列表中。
3. 显示「已就绪」后，在「连接信息」逐项复制，或一键复制全部地址。两台客户端填写同一套地址、使用不同账号。
4. 到「联机账号」新建玩家账号；邮箱可以留空，会生成不发送邮件的占位字段。账号持久保存在开服电脑，正常重启无需重建。
5. 游戏结束后点击「停止服务」。关闭窗口也会停止**本窗口启动**的服务，运行中会询问确认。其他窗口或目录启动的服务不由它停止。

窗口同时支持启动两种模式；模式切换不会停止另一种模式。两种模式共享监听地址，因此修改地址前需要停止两种服务。需要命令行时运行 `Server-CLI.cmd`，原菜单和参数继续保留。

默认地址为 `127.0.0.1`，只供本机访问。局域网、Tailscale 或其他虚拟局域网需提供双向 IPv4 通信；双机游玩时选择开服电脑在该网络上的地址。工具不自动更改 Windows 防火墙，请按下表放行所用模式的端口。

| 用途 | 普通联机 | BBSC 无缝联机 |
|---|---|---|
| 合作服务器 TCP | IP:31313 | IP:31413 |
| STUN UDP | 31314 | 31414 |
| WebAPI HTTP | http://IP:31315 | http://IP:31415 |
| BBSC 游戏服务 HTTP | 不含普通版游戏服务 | http://IP:20443 |
| BBSC Relay TCP | 不需要 | IP:20444 |

普通版的留言、血迹等游戏服务可继续使用原有地址；这个包的普通模式提供 shadNet 合作服务。
如普通版客户端仍有旧服务器的 host_overrides 自定义规则，需要在下一轮测试时一起核对，单改合作服务器字段可能不足。

## 账号管理

- **查看／刷新**：只显示账号 ID、名称、邮箱字段和状态，不显示密码、哈希、盐值或令牌。
- **新建**：先在当前窗口启动对应服务，通过服务自身的注册接口创建。邮箱留空即可；每位同时在线的玩家使用不同账号。
- **验证密码**：本地核对，不登录或占用游戏会话；运行和停止状态均可使用。
- **改名**：先停止对应服务，保留 ID、密码和其他账号属性。改名后，客户端填写的在线 ID 也要改为新名称，大小写保持一致。
- **重置密码**：先停止对应服务，输入两次新密码；不显示或找回旧密码。
- **删除**：先停止对应服务，选中账号并输入完整名称确认。只删除此模式的登录账号及其好友／排行关联，不修改玩家电脑上的角色存档，也不批量清除 BBSC 留言数据。

新建、改名、重置、删除前会在 `backups/模式/` 创建一致性数据库备份并检查完整性；「备份」按钮打开对应位置。账号列表的选择在后台再次核对 ID 和名称，过期记录不会直接执行修改。其他命令行实例正在使用同一模式时，修改会被拒绝。

管理窗口通过本机进程管道通信，不新增网络管理端口。GUI 的账号凭据通过标准输入传递，不放进命令行参数、设置文件或日志。高级命令行入口仍使用上游示例工具，其凭据会短暂出现在本机进程参数中。

需要恢复账号备份时，先退出对应服务并保留当前完整 `db` 目录，再在新的空 `db` 目录中放入备份，文件名改为 `shadnet.db`。不要把旧的 WAL／SHM 文件与恢复副本混在一起。账号备份不包含玩家角色存档。

目录说明：

- `normal/db`：普通联机数据库；`bbsc/db`：无缝联机数据库。
- `normal/logs`、`bbsc/logs`：各自运行日志。
- 各模式的 `shadnet.cfg`：首次启动生成，含随机注册密钥，请妥善保管。
- `bbsc/online-data.json`：无缝游戏服务数据。
- `backups/normal`、`backups/bbsc`：账号修改前的数据库备份。
- `runtime`：共用 Qt、Python 运行库；`bbsc-game`：游戏服务与 Relay 源码。
- `source-manifest.json`、`BUILD-INFO.json`、`licenses`：固定源码版本、构建信息与许可文件。

测试版范围：保留已验证过的 4/6 字节 STUN 兼容修复；BBSC 使用独立 WebAPI 端口。
BBSC Relay 是单组玩家共享广播，未提供房间隔离；适用于互相信任的一组玩家，不要直接作为公开多人平台使用。
当前提供本地管理窗口；未安装 Windows 常驻服务，也不自动配置防火墙。
备份时先停止服务，再复制 `normal`、`bbsc` 和 `server.json`。

构建来源与修改：shadNet 固定版本和 BBSC 固定版本见 `source-manifest.json`。
shadNet 仅加现有 STUN 兼容修复、启用账号工具的构建目标；BBSC 增加显式 `--shadnet-webapi` 参数，并修正本机登录地址与实际监听地址不一致的问题。
原作者与第三方许可保留在 `licenses`，BBSC 原始署名同时保留在 `bbsc-game`。
完整源码包和 Linux 配方与二进制一起提供，详见 https://github.com/ytq77/TheHuntServer 。

## 更新已有 Windows 服务

先让玩家退出，并停止对应服务（旧命令行窗口按 Ctrl+C），备份旧目录。将新版本解压到新的目录，再从旧目录复制持久数据：

- 根目录 `server.json`：已选监听地址。不要用新包的回环默认值覆盖它。
- `normal/shadnet.cfg`、`normal/db/`：普通模式配置与账号。
- `bbsc/shadnet.cfg`、`bbsc/db/`、`bbsc/online-data.json`：无缝模式配置、账号与在线数据。
- 如自行修改过各模式的 `worlds.cfg`、`scoreboards.cfg`，一并保留；日志可另外归档。

只复制旧目录中实际存在的上述数据，不复制旧版 exe、runtime 或 bbsc-game。新目录保留新程序和运行库，旧目录留作回滚；不要让两份服务同时占用同一组端口。启动后核对窗口中的地址和已有账号登录，再让两人进入游戏。

服务端账号不是角色存档。迁移服务端不需要把玩家的游戏存档上传到开服电脑。

## 无缝召唤轮询

新构建的无缝模式默认采用 2 秒搜索／发布间隔，普通模式不受影响。部分在线列表查询在未摇铃时也会发生，请求及日志量会增加；战斗同步频率不由此控制。作用范围、验证结果和恢复原间隔的方法见 [召唤轮询说明](summon-polling.md)。源码更新不会自动替换现有安装。
