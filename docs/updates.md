# 检查更新与国内网络

启动程序后会在后台检查一次，沿用本机保存的更新频道、HTTP 代理和 GitHub 加速设置。发现新版本时，主界面的「检查更新」按钮变为「发现新版」，将鼠标放在按钮上可查看版本号；不会自动弹窗、下载或安装。检查失败不影响游戏、开服或账号管理，仍可点击按钮手动重试。

The Hunt 启动器和 The Hunt Server 分别检查自己的 GitHub Release，不会把服务端包装进客户端。点击窗口中的「检查更新」，再点击弹窗中的「检查更新」查询版本。当前使用预览版时，默认勾选「接收预览版更新」；可以取消，只检查稳定版。

版本按数字比较，例如 `preview.10` 高于 `preview.9`。仅展示已上传对应 Windows 完整包的发布版本；本机开发版本高于已发布版本时，不提示降级。

## 网络选项

- 两项留空：直接访问 GitHub。
- HTTP 代理：用于程序内的版本查询和自动下载，可填写本机代理软件提供的 HTTP 地址，例如 `http://127.0.0.1:7890`。端口以自己的软件配置为准，不是固定值；不填写账号密码。
- GitHub 下载加速前缀：填写自己信任的 HTTPS 加速站前缀，例如 `https://你的加速站/`。下载时，程序会在完整 GitHub 下载地址前加上这个前缀；「手动下载」由浏览器接管，「自动更新」由程序下载并校验。

版本查询优先直连或使用填写的 HTTP 代理，网络请求失败后才尝试以 GitHub 加速前缀访问 API。部分加速站只支持 Release 文件、不支持 API，遇到这种情况请用 HTTP 代理查询版本。未内置或推荐任何第三方加速站，未关闭 HTTPS 证书校验。

HTTP 代理作用于程序内查询和自动下载；浏览器手动下载使用它自己的代理设置。GitHub 加速前缀可用于两种下载方式，但不改变浏览器代理。

这些选项只影响更新功能，不修改游戏联机、Tailscale、系统代理或 SSH 设置，不读取、发送游戏账号及服务器管理凭据。成功检查后将网络选项和频道保存在本机 `update-settings.json`，发行包排除此文件。

## 自动更新

点击「自动更新」前，客户端请退出游戏、结束存档等操作；开服管理器请先停止两种服务。程序先下载完整 Windows 包，并按 GitHub Release 接口提供的 SHA256 和大小校验，之后退出自身，由独立助手验证包内清单、备份程序文件、替换并重新打开。

存档、凭据、联机地址、账号数据库、拾取和世界恢复记录保持原位。服务端已有的 `server.json`、`worlds.cfg`、`scoreboards.cfg` 也会保留。备份只包含被替换的程序文件，位于安装目录 `update-backups/`，不复制账号库或角色存档。更新仍会保留旧版本遗留的额外文件，不自动清理用户目录。

下载阶段可以关闭更新弹窗来取消；替换阶段使用独立进度窗口。文件被占用或替换失败时，会尝试恢复已替换的程序；若恢复本身受阻，会显示备份位置以便人工恢复。更新期间阻止同目录程序再次启动。磁盘断电等进程外中断无法保证自动回滚，请保留 `update-backups/` 备份。

下载可以走填写的 GitHub 加速前缀，但自动安装的校验值必须来自直连 GitHub API（可经过填写的 HTTP 代理，保留 GitHub 的 HTTPS 校验）。仅通过第三方加速站取得版本信息时，仍可手动下载，自动安装按钮保持禁用；程序不把加速站自报的哈希当作独立校验依据。

本功能更新的是 Windows 客户端和 Windows 开服管理器各自的程序，不替换普通版官方启动器，也不自动升级云服务器。第一次安装带自动更新功能的版本仍需手动下载；之后才能在程序内更新。

测试包含版本排序、稳定/预览频道、草稿与未完成附件过滤、下载地址归属校验、中文说明、代理地址校验、私有数据保持不变、损坏或越界包拒绝、锁定文件后的回滚、应用仍运行时阻止安装，以及等待父进程退出后重新启动新版。第三方加速站是否可用，需使用自己的地址实际测试。
