# 在客户端查看服务与管理账号

「服务器管理」供自建服务管理员使用，支持：

- 查看这套 Compose 项目的容器运行／健康状态。
- 列出联机账号的 ID、名称、管理员与封禁状态。
- 新建账号：先在服务器 `backups/` 创建 SQLite 一致性备份并验证，再通过固定版本的 `shadnet-sample` 注册和验证登录。
- 验证账号密码。它会短暂登录，请先退出该账号在所有电脑上的游戏。

本版不提供删除账号、改名、重置密码、改端口或启停服务器。角色存档在玩家电脑上，联机账号列表不是角色列表。
没有为了验证新建按钮而给实际服务器添加测试账号；注册路径已有模拟响应与备份测试，真实注册需由管理员按需操作。

## 连接准备

1. Windows 安装 OpenSSH 客户端；使用已有的服务器 SSH 密钥或 ssh-agent。
2. 在终端先连接并核对可信主机指纹。页面不会自动接受新指纹，也不会关闭校验。
3. 在页面填写 SSH 别名或 `用户@公网地址`、SSH 端口和服务器上的 BBSC Compose 目录。
4. 选择本机私钥路径；若配置了 SSH 别名或 ssh-agent，可以留空。
5. 如果已有专用 `known_hosts`，选择该文件；留空则使用 OpenSSH 的默认记录。
6. 若 SSH 用户不是 root，可使用已配置的 `sudo -n`。服务器需有 Python 3、Docker Compose 与读取本配方数据的权限。
7. 点击「刷新状态与账号」，确认显示的是目标服务器及本套服务。

管理员连接可以走公网 SSH，游戏数据继续走 Tailscale；它们不必使用同一个地址。
本机保存 `server-admin.json`，只保存连接信息和密钥／指纹文件的路径，不读取、复制或打包私钥。
加密私钥需先加入 ssh-agent；后台连接不弹出密码输入框，不保存 SSH 密码。
服务器管理员权限由 SSH 及 sudo 决定，不由游戏联机账号授予。

## 实现与权限边界

客户端通过已认证 SSH 执行随包携带的一次性 Python 管理代码，读取指定 Compose 项目。
没有在服务器安装常驻管理服务，也不新增可公开访问的管理端口。
账号列表通过只读 SQLite 连接读取指定公开字段，不查询哈希、盐值或令牌。
注册密钥只在服务器本地读取；账号密码通过子进程和 SSH 的标准输入传递，不放在本机命令行、配置文件或日志中。

上游 `shadnet-sample` 接收命令行参数，因此服务器上执行注册／验证的瞬间，具有足够权限的本机管理员仍能查看该进程参数。
此页面适用于自己管理的可信服务器，不提供对管理员隐藏账号密码的保证。
新建失败或超时后请先刷新账号列表；没有完整成功确认时，不应直接反复注册。

状态页显示健康不等于 UDP 正常、账号认证成功或两人已经召唤成功，双人测试仍需在游戏内完成。
本项目本轮已经通过真实 SSH 验证现有私人环境的两项服务健康及账号列表；没有修改现有账号、监听端口和运行配置。
